# Фирменный знак и иконки

Все иконки собираются из одного мастера, чтобы размеры не разъезжались.

```
brand/mark.html         исходник знака (HTML + CSS, палитра и гарнитура сайта)
brand/mark-master.png   мастер 1024×1024, отрендеренный из mark.html
brand/build-icons.py    сборка всех размеров из мастера
```

## Пересобрать иконки

```bash
pip install pillow
python3 brand/build-icons.py
```

## Изменить сам знак

1. Поправить `brand/mark.html`.
2. Отрендерить мастер 1024×1024 из этого файла в `brand/mark-master.png`
   (любым способом: скриншот страницы в браузере при окне 1024×1024).
3. Запустить `build-icons.py`.

## Что куда идёт

| Файл | Размер | Кто читает |
| --- | --- | --- |
| `src/app/favicon.ico` | 16 + 32 + 48 | **Выдача Яндекса и Google**, вкладки старых браузеров |
| `src/app/icon.png` | 512 | Вкладка современных браузеров |
| `src/app/apple-icon.png` | 180 | Домашний экран iPhone |
| `public/icon-192.png` | 192 | Android, ярлык |
| `public/icon-512.png` | 512 | Экран запуска при установке как приложение |
| `public/icon-maskable.png` | 512 | Android, который режет иконку под свою форму |

## Почему именно `favicon.ico`

Поисковые системы берут иконку для выдачи **не** из `<link rel="icon">`.
Они отдельным запросом забирают `/favicon.ico` из корня домена, и им нужен
многоразмерный `.ico`: Яндекс использует кадр 32, Google — 48. Набор PNG,
который отлично работает во вкладке, в выдаче не даёт ничего.

Файлы в `src/app/` отдаются из корня по соглашению Next.js App Router:
`src/app/favicon.ico` → `/favicon.ico`. Теги в `<head>` фреймворк
подставляет сам, руками их прописывать не нужно.

## Начертание

Знак набран гротеском Golos Text, а не заголовочной Prata: на 16–32
пикселях засечки дидона превращаются в кашу, а выдача показывает именно
эти размеры. Проверять результат нужно на реальном размере, а не на
мастере.
